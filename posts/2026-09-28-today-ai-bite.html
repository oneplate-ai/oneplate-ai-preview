오늘 AI 한입

2026년 9월 28일

이번 호는 AI 확장을 검토·게시 가능한 플러그인으로 만들고, 비개발자의 업무 제작을 돕고, 하나의 작업 공간에서 문서·앱·자동화를 연결하는 흐름을 살펴봅니다.
기능이 많아질수록 실제 제공 범위와 데이터·권한·사람의 확인 절차를 함께 살펴봐야 합니다.

1. Anthropic이 Claude용 플러그인을 만들고 검토하는 경로를 열었습니다. Anthropic 공식 발표

Anthropic은 9월 25일 Claude용 플러그인을 만들고 디렉터리에 제출할 수 있는 경로를 소개했습니다.
플러그인은 MCP 커넥터와 Agent Skills를 묶을 수 있으며, 개발자는 제출 포털에서 원격 MCP 서버 하나 또는 MCP 서버와 스킬을 묶은 저장소를 제출할 수 있습니다.

제출 과정에는 자동 검증과 안전성 검사, 검토 상태 확인, 승인 후 게시 시점 선택이 포함됩니다.
Anthropic은 게시 뒤 제품별 설치 수와 버전별 사용 분석도 제공한다고 설명했습니다.

  • 누구에게 해당하나: Claude와 사내 도구·데이터를 연결하는 확장 기능을 만들려는 개발자와 조직입니다.
  • 현재 상태: 제출 포털은 유료 Claude 요금제 개발자에게 열려 있으며, 디렉터리 등록은 승인 절차를 거칩니다.
  • 왜 중요한가: AI 확장이 개인별 설정을 넘어 검토·게시·분석이 포함된 배포 단위로 바뀌기 때문입니다.
  • 주의할 점: MCP 서버와 플러그인에 연결되는 데이터·권한을 먼저 제한하고, 자동 안전성 검사만으로 조직의 보안 검토를 대신해서는 안 됩니다.

2. OpenAI가 Codex를 비개발자의 맞춤형 업무 제작 사례로 소개했습니다. OpenAI 공식 사례

OpenAI는 9월 25일 차량 관리 소프트웨어 회사 Proaction의 Codex 활용 사례를 공개했습니다.
Proaction의 공동 창업자는 고객의 차량과 업무 흐름에 맞춘 대화형 데모를 직접 만들고, 통화 녹음·이메일·스프레드시트의 맥락을 바탕으로 후속 업무를 정리한다고 설명했습니다.

OpenAI의 사례에 따르면 Proaction은 Codex 플러그인으로 여러 업무 도구의 정보를 모으고, 데모 제작에 드는 엔지니어링 시간을 줄였다고 합니다.
이 수치는 Proaction의 자체 추정이므로 일반적인 생산성 보장으로 받아들이면 안 됩니다.

  • 누구에게 해당하나: 반복적인 업무 흐름을 맞춤형 데모·문서·자동화로 바꾸려는 소규모 팀입니다.
  • 현재 상태: OpenAI가 공개한 고객 사례이며, Codex의 기능·플러그인·접근 조건은 계정과 제품 환경에 따라 달라질 수 있습니다.
  • 왜 중요한가: AI 코딩 도구가 개발자만의 도구가 아니라 영업·지원·제품 업무의 제작 도구로 확장되는 모습을 보여 주기 때문입니다.
  • 주의할 점: 고객 자료와 녹음·이메일을 연결할 때 권한과 개인정보를 먼저 확인해야 하며, 회사가 제시한 시간 절약·매출 수치는 독립 검증 결과가 아닙니다.

3. Microsoft가 Copilot 안에서 대화·문서·앱 제작·자동화를 묶었습니다. Microsoft 공식 발표

Microsoft는 9월 25일 새 Copilot의 Home·Code·Autopilot 기능을 소개했습니다.
Home은 Chat과 Cowork를 한 시작 화면에 모으고, Code는 자연어로 대시보드·추적기·자동화 같은 작은 업무용 도구를 만들 수 있도록 하며, Autopilot은 사용자가 자리를 비운 동안에도 정해 둔 작업을 이어가는 에이전트로 설명됩니다.

Word·Excel·PowerPoint 문서를 Copilot 안에서 만들고 수정하는 Office in Copilot도 함께 소개됐습니다.
Home과 Code는 Frontier 프로그램에서 순차 제공되고 Autopilot은 9월 말 비공개 프리뷰로 확대될 예정이라고 Microsoft는 밝혔습니다.

  • 누구에게 해당하나: Microsoft 365 안에서 문서 작업과 반복 업무를 연결하려는 개인·팀·조직입니다.
  • 현재 상태: 일부 기능은 Frontier 프로그램 또는 프리뷰로 제공되며, 일반 제공 시점과 사용 권한은 기능별로 다릅니다.
  • 왜 중요한가: AI를 질문에 답하는 창이 아니라 문서·앱·자동화를 만드는 작업 공간으로 묶으려는 방향을 보여 주기 때문입니다.
  • 주의할 점: 에이전트가 읽고 수정할 수 있는 파일·채널·업무 범위를 조직 정책으로 제한하고, 자동 실행 결과를 사람이 확인해야 합니다.

오늘의 한 줄 정리.

이번 소식들은 AI가 더 자연스럽게 대화하고, 더 많은 업무를 만들고, 더 오래 작업하는 방향으로 넓어지고 있음을 보여 줍니다.
편리함을 실제 업무에 연결하려면 제공 상태보다 데이터 권한과 사람의 승인 지점을 먼저 정해야 합니다.
