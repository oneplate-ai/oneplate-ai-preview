오늘 AI 한입

2026년 9월 28일

이번 호는 대화형 협업 도구로 넓어지는 AI 코딩 지원, 보안 수정에 축적되는 작업 기억, 개발 조직의 검토 과정을 측정하는 지표를 살펴봅니다.
기능이 자동화되어도 권한·저장 정보·최종 검토 범위는 사람이 확인해야 합니다.

1. GitHub Copilot이 Slack과 Microsoft Teams에서 더 많은 작업 맥락을 다룹니다. GitHub 공식 변경 안내

GitHub는 9월 25일 Slack과 Microsoft Teams용 Copilot 업데이트를 안내했습니다.
공식 안내의 대표 예시에는 대화 중 사용 중인 모델을 확인하고 다른 모델로 전환하는 흐름, Slack에서 파일을 공유하는 흐름처럼 대화와 GitHub 작업을 더 가깝게 잇는 기능이 포함됩니다.

이는 개발자가 협업 대화창을 떠나지 않고 작업 맥락을 이어갈 수 있다는 의미입니다.
다만 어떤 파일과 대화가 Copilot에 전달되는지, 조직 관리자가 허용한 기능인지 먼저 확인해야 합니다.

  • 누구에게 해당하나: Slack이나 Microsoft Teams에서 개발 업무를 조율하며 GitHub Copilot을 사용하는 팀입니다.
  • 현재 상태: GitHub는 9월 25일 변경 안내로 공개했으며, 실제 기능과 관리 설정은 조직·제품 환경에 따라 다를 수 있습니다.
  • 왜 중요한가: AI 코딩 지원이 코드 편집기 안에서만 작동하는 것이 아니라 팀 대화의 흐름으로 이동하기 때문입니다.
  • 주의할 점: 파일 공유와 모델 전환을 자동 승인으로 오해하지 말고, 조직 정책과 전송 범위를 확인해야 합니다.

2. Copilot의 에이전트형 자동 수정이 Copilot Memory를 활용합니다. GitHub 공식 변경 안내

GitHub는 9월 25일 에이전트형 자동 수정 기능이 Copilot Memory를 활용한다고 발표했습니다.
사용자가 두 기능을 켜면 자동 수정이 기존 메모리에서 저장소에 맞는 보안 수정 맥락을 참고하고, 수정 과정에서 얻은 패턴을 향후 사용을 위한 메모리로 저장할 수 있습니다.

이렇게 쌓인 패턴은 추가 보안 경고를 해결하거나 코드 리뷰·클라우드 에이전트 같은 다른 Copilot 기능에 저장소 고유의 안전한 개발 방식을 알려주는 데 쓰일 수 있습니다.
하지만 메모리에 무엇이 저장되고 어디에 적용되는지 확인하지 않으면 오래된 규칙이나 잘못된 패턴이 반복될 수 있습니다.

  • 누구에게 해당하나: GitHub의 보안 경고를 자동 수정하고 저장소별 개발 규칙을 관리하는 팀입니다.
  • 현재 상태: GitHub는 에이전트형 자동 수정과 Copilot Memory 모두 공개 프리뷰라고 밝혔습니다.
  • 왜 중요한가: AI가 한 번의 답변이 아니라 저장소의 과거 수정 경험을 참고해 다음 보안 작업에 활용하는 방식이기 때문입니다.
  • 주의할 점: 프리뷰 기능인 만큼 저장·재사용되는 메모리의 범위와 수정 결과를 사람이 검토해야 합니다.

3. GitHub Copilot 사용량 API가 풀 리퀘스트 검토 단계를 나눠 보여줍니다. GitHub 공식 변경 안내

GitHub는 9월 25일 기업·조직용 Copilot 사용량 지표에 풀 리퀘스트 검토 단계별 시간을 추가했다고 안내했습니다.
저장소 수준의 보고서에서 풀 리퀘스트가 검토 과정의 각 단계에 얼마나 머물렀는지 확인할 수 있도록 새로운 pull_request_review_times 배열을 제공한다는 내용입니다.

이 지표는 AI가 코드를 잘 작성했는지만 보는 대신, 검토가 어디에서 오래 걸리는지 조직이 살펴보게 합니다.
숫자가 높다고 곧바로 Copilot의 효과나 개발자 생산성을 뜻하는 것은 아니므로, 변경 규모·팀 절차·사람의 승인 시간을 함께 해석해야 합니다.

  • 누구에게 해당하나: Copilot을 조직 단위로 운영하며 개발 흐름을 분석하는 관리자와 개발팀입니다.
  • 현재 상태: GitHub는 기업 및 조직 저장소 수준의 사용량 보고서에 추가된 API 지표로 안내했습니다. 사용 가능한 보고서와 권한은 계정 설정을 확인해야 합니다.
  • 왜 중요한가: AI 도입을 단순 사용 횟수가 아니라 실제 코드 검토 흐름과 연결해 볼 수 있기 때문입니다.
  • 주의할 점: 지표는 원인을 자동으로 설명하지 않으며, 개인 평가나 성과 순위를 만드는 단독 근거로 사용해서는 안 됩니다.

오늘의 한 줄 정리.

AI 코딩 도구가 대화·기억·측정으로 넓어질수록, 편리함보다 권한과 저장 정보, 사람의 검토 기준을 먼저 정하는 일이 중요합니다.
